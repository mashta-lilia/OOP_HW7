## Розв'язки

### Завдання 1. Абстрактна фабрика: Mercedes
Нове сімейство складається з трьох нових класів: `Mercedes : Car`, `MercedesEngine : Engine` і `MercedesFactory : ICarFactory`.
Старі класи та клієнт не змінювались. Клієнт працює лише з `ICarFactory`, тому про Mercedes він не знає.

Що виправлено порівняно з посібником:
- `Engine.GetPower` став `abstract` (у прикладі він був порожнім `virtual`).
- Фабрики реалізують інтерфейс звичайно, а не явно (`ICarFactory.CreateCar`).

```
Toyota
Toyota Engine 3.2
Ford
Ford Engine 4.4
Mercedes
Mercedes Engine 5.0
```

### Завдання 2. Builder: MargaritaPizzaBuilder
`MargaritaPizzaBuilder` перевизначає три кроки: тісто, соус і начинку.
Директор `Waiter` і продукт `Pizza` не змінювались: директор знає порядок кроків, але не знає, яку піцу будує.
Також виправлено:
- у посібнику `SpicyPizzaBuilder` ніде не використовувався, тепер у демонстрації будуються всі три піци;
- описку «Sause» замінено на «Sauce».

```
--- MargaritaPizzaBuilder ---
Dough: thin
Sauce: tomato
Topping: mozzarella+basil
```

### Завдання 3. Mediator: третій колега
Додано `ConcreteColleague3`. У посібнику посередник пересилав повідомлення «від першого до другого, інакше першому», а для трьох учасників це вже не працює. Тому `ConcreteMediator` тепер **пересилає повідомлення всім, крім відправника**.
Колеги, як і раніше, не мають посилань один на одного.
Спільні методи `Send` і `Notify` винесено в базовий клас `Colleague`, щоб не дублювати код.

```
Colleague3 sends: Hello!
  Colleague1 gets message: Hello!
  Colleague2 gets message: Hello!
```

### Завдання 4. Decorator: Ялинка
- `ChristmasTree` — компонент; він має методи `Describe()`, `CanGlow` і `Glow()`.
- `FirTree` — звичайна ялинка.
- `TreeDecorator` — базовий декоратор, який тримає ялинку всередині й делегує їй виклики.
- `Ornaments` — прикраси. Вони додають **поля** (вид, кількість, колір).
- `Garland` — гірлянда. Вона додає **поведінку**: після неї `Glow()` світиться.

Декоратори можна комбінувати в будь-якому порядку, наприклад кульки + шишки + гірлянда або дві гірлянди.
Для цього не потрібен окремий підклас на кожну комбінацію.

```
Ялинка 1.8 м
  Ялинка не світиться: на ній немає гірлянди.
Ялинка 2.2 м + кульки (30 шт., золоті) + шишки (10 шт., срібні) + гірлянда (різнокольорова)
  Світиться різнокольорова гірлянда ✨
Ялинка 1.5 м + гірлянда (біла) + гірлянда (синя)
  Світиться біла гірлянда ✨
  Світиться синя гірлянда ✨
```

### Завдання 5. Prototype: Трикутник
`Triangle` реалізує `IFigure`, а `Clone()` повертає новий трикутник з тими ж сторонами.
Конструктор перевіряє нерівність трикутника.
Також у `Rectangle.GetInfo` виправлено переплутані довжину й ширину і російську літеру «и».

```
Трикутник зі сторонами 3, 4, 5
Трикутник зі сторонами 3, 4, 5
  Це різні об'єкти: True
```

### Завдання 6. Власні завдання (Factory Method і Adapter)

**6а. Factory Method.**
*Умова:* у прикладі `ConcreteCreator` вибирає продукт через `switch`. Потрібно додати новий продукт без зміни наявного коду.
*Розв'язок:* кожен продукт має свого творця (`ReportCreator`, `InvoiceCreator`, `ContractCreator`), який перевизначає фабричний метод `CreateDocument()`.
Новий документ «Договір» додано двома новими класами, а `switch` взагалі не потрібен. Це відповідає принципу відкритості/закритості (OCP).

**6б. Adapter.**
*Умова:* окрім старої розетки, підключити ще одну несумісну систему — американську розетку на 110 В — не змінюючи клієнта.
*Розв'язок:* новий `AmericanSystemAdapter` реалізує `INewElectricitySystem` і всередині викликає `AmericanElectricitySystem`. Клієнт `ElectricityConsumer` не змінювався.

```
6а. Factory Method:
  Створено документ «Звіт» (ReportDocument)
  Створено документ «Рахунок» (InvoiceDocument)
  Створено документ «Договір» (ContractDocument)

6б. Adapter:
  Ноутбук заряджається: 220 В, сучасна євророзетка
  Ноутбук заряджається: 220 В, стара вузька розетка → через перехідник
  Ноутбук заряджається: 110 В, американська розетка з пласкими контактами → трансформатор 110→220 В
```

## Відповіді на запитання до теми

1. **Різновиди шаблонів.** За GoF їх поділяють на три групи:
   - **породжувальні** (як створювати об'єкти): Abstract Factory, Factory Method, Builder, Prototype, Singleton;
   - **структурні** (як складати класи та об'єкти в більші структури): Adapter, Bridge, Composite, Decorator, Facade, Flyweight, Proxy;
   - **поведінкові** (як об'єкти взаємодіють і розподіляють обов'язки): Chain of Responsibility, Command, Iterator, Mediator, Memento, Observer, State, Strategy, Template Method, Visitor, Interpreter.
2. **Абстрактна фабрика.** Інтерфейс для створення *сімейства* пов'язаних об'єктів без вказівки їхніх конкретних класів.
   Клієнт отримує фабрику й створює через неї узгоджені між собою продукти (машину й двигун однієї марки).
   Нове сімейство додається легко, а новий *вид* продукту — важко, бо доведеться змінити інтерфейс фабрики.
3. **Прототип.** Новий об'єкт створюється копіюванням наявного (`Clone()`), без знання його класу.
   Корисно, коли створення дороге або клас визначається лише під час виконання.
   Копія буває поверхнева або глибока.
4. **Одиночний об'єкт (Singleton).** Гарантує, що клас має лише один екземпляр, і дає до нього глобальну точку доступу.
   Реалізація: приватний конструктор і статична властивість `Instance`. У C# найпростіше використати `static readonly` або `Lazy<T>`, щоб він був потокобезпечним.
   Мінус: це по суті глобальний стан, і його важко підмінити в тестах.
5. **Міст (Bridge).** Відокремлює абстракцію від реалізації, щоб вони змінювались незалежно.
   Наприклад, `Shape` має посилання на `IRenderer`: фігури й способи малювання розширюються окремо, без вибуху кількості підкласів.
6. **Ланцюг обов'язків.** Запит передається вздовж ланцюжка обробників. Кожен або обробляє його, або передає наступному.
   Відправник не знає, хто саме обробить запит. Приклади: обробка подій, middleware в ASP.NET, погодження заявок за сумою.
7. **Декоратор.** Динамічно додає об'єкту нові обов'язки, обгортаючи його об'єктом із тим самим інтерфейсом. Це гнучка альтернатива наслідуванню.
   Обгортки можна комбінувати (див. завдання 4). Приклад у .NET: `BufferedStream` поверх `FileStream`.
8. **Ітератор.** Дає послідовний доступ до елементів колекції без розкриття її внутрішньої будови.
   У C# це `IEnumerable<T>`/`IEnumerator<T>`, `foreach` і `yield return`.
